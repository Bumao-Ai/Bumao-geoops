Project registry · six required fields

项目登记

项目编号、名称、类型、区域、坐标参考、高程基准六项必填；编号唯一，缺一项即拒绝。

项

Projects 项目册—

项目是任务、数据集、成果追溯的根。登记后不可用同编号重复建项。

Register project 登记项目

需要 project:write。缺字段或编号重复时服务端原文拒绝，不落半条记录。
Task engine · state machine

任务台账

七态状态机：非法迁移被拒且不落半条记录；完成与取消必须写理由。

务

Survey tasks 测绘任务—

Write actions 写操作需令牌

新建任务 POST /api/v1/tasks
需要 task:create。服务端在读 body 之前校验令牌；没有权限就写不进去。
迁移状态 POST /api/v1/tasks/<id>/transitions
需要 task:transition。目标状态只列该任务当前允许迁移的项，非法边会被服务端拒绝。
Model / tool / agent · honest availability

AI 资源

模型、工具、Agent 分开登记。builtin 必须是真实实现，external 路径不存在即标不可用；Agent 引用未知依赖直接拒绝。

器

Resource catalog 资源目录—

可用性不是标签：builtin 适配器必须是本仓真实实现，external 必须指向存在的路径；不可用会带原因。Agent 引用未登记的模型或工具会被拒绝。

Register resource 登记资源

需要 catalog:write。外部路径必须已存在且可读；不可用的资源仍会入册，但会写明原因，不会伪装可用。
Geospatial data · hash and CRS on read

数据接入

数据集登记时读真实文件算 sha256，CRS 取自 sidecar 或 classic GeoTIFF 头；复核重探测，文件内容变化即 FAIL。

据

Datasets 数据集—

Register dataset 登记数据集

同名 sidecar <file>.json 需写 {"crs":"EPSG:4547"}；无 CRS 或文件不存在会被拒绝。BigTIFF 与像元解码明确不支持。
Workflow · gate → compare → register

流程运行

一次运行里规则门在前、登记在后：判定不过，成果不会被登记。

流

Run history 运行历史—

运行完成才写一行日志（fsync 后才返回）；重复 run_id 拒绝，坏行整份拒载。

Chain 登记链路

  • GATE规则门 · CRS / 格距 / 两期一致性
  • COMPUTE变化检测 · 逐格差分 + 4 邻域斑块 + 最小面积
  • WRITE掩膜写出 · 源头信息保留，nodata 仍为 nodata
  • REGISTER成果登记 · 真文件、真 sha256、绑已登记成果
Rule packs · declarative

规则包

规则是数据不是代码：校验器缺失或异常判 ERROR，条件不满足判 SKIPPED，两者都不升格为 PASS。

规

Loaded packs 已载规则包—

规则包整包校验后装载：缺字段、severity 非法、id 重复、与已载冲突都会整包拒绝，不半装。
Quality assurance · three layers

质量检查

文件与结构、空间数据、专业成果验证三层。第三层没有人工抽样与书面依据，只能是 NOT_RECORDED，汇总结果只能是 PARTIAL。

质

Run check 发起质检

需要 quality:write。质检报告会写入 var/quality 并以 QualityReport 入域，不是只在前端算一遍。

Latest result 本次判定

待

尚未执行

选择数据集或成果后执行三层质检；结果、逐项证据与报告路径会出现在这里。

Quality reports 质检报告—

Deliverables · versions and archive

成果簿

成果登记读真实文件：哈希、大小、路径当场记录；人工审核通过后才 accepted，之后才允许归档。

果

Registered deliverables 已登记成果—

「归档」只在 accepted 后开放。归档不会改动文件，只把成果状态与归档人、时间写入域对象。

Register deliverable 登记成果

需要 deliverable:write。路径必须存在且为普通文件；符号链接与目录一律拒绝。

Registered files 文件簿—

Human review · final acceptance

审核签认

成果只有经人工通过才置为 accepted；驳回或返工必须写意见，已签认的成果拒绝二次审核。

审

Review records 审核记录—

Submit review 提交审核

需要 review:write。记录写入同时改成果状态；通过即最终验收，驳回或返工不签认。
Trace · task to sources and signature

反向追溯

从任务串回项目、数据集、运行、规则、成果、文件与审核；缺失的一环写 NOT_RECORDED，不拿推断补链。

溯

待

输入已登记任务 id，系统按项目→数据集→运行→规则→成果→文件→审核逐环取证。

System · roles and permission matrix

系统设置

这里展示服务端真实权限矩阵与调用方令牌授权，不在前端伪造角色。没有令牌就只能读公开接口。

设

Caller 调用方读取中

令牌只存本页 sessionStorage，不会写入磁盘。权限由服务端 api/security.py 的 PERMISSIONS 与授权文件决定。

Storage 存储与策略

域对象、运行日志、成果簿与质检报告的真实配置状态在这里展示；未配置就写「未配置」。

Role matrix 角色与权限

Permission keys 权限键

权限键是写操作的边界。GET 公开接口不要求令牌；审计读取与所有写入口都要求对应权限。
